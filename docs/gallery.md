# The public gallery and the daily art pipeline

Every day the wall hangs one new piece of generative art (a GLSL shader with a title and an
artist's statement). Each piece is also published to a small public website, built from this repo
with GitHub Pages. This page explains how the pipeline works and what to change to run it for your
own wall. None of it is needed to run the wall itself: without it the wall still shows its
gallery, and the "Art of the day" slot falls back to the bundled editions and an offline piece.

## How a day goes

1. **Compose.** Around 05:00 (the Pi's local time) the wall, or the GitHub Actions workflow
   `.github/workflows/daily.yml` at 04:40 Zürich time, asks an AI model to write today's piece
   after looking at a contact sheet of a public Pinterest board (`WALL_MOODBOARD`, read through the
   board's RSS feed). Each day also gets an art direction from `display/directions.py` (a colour
   family, a light/mid/dark ground, a kind of form) so neighbouring days differ.
2. **Check.** The shader must compile, and a simulated minute of it must be calm: no flicker, not
   blinding, not blank. Failures go back to the model with the reason.
3. **Curate.** A second model call looks at rendered stills and scores them. Anything under 7/10
   goes back with a note, up to six attempts (`daily.generate`); the best one is hung.
4. **Publish.** The public fields (name, description, palette, the shader source and a still) are
   committed to `gallery/` in the repo. The `Fortuna gallery` workflow (`gallery.yml`) rebuilds the
   site with `tools/build_gallery.py` and deploys it to GitHub Pages.
5. **Close the day.** At midnight the wall finalises the piece with the day's listening (what the
   microphone heard shaped the piece) and a post is written from the final still. Song titles and
   token counts never leave the wall (`display/publish.py` strips `songs` and `tokens`).

The workflow makes the piece in the cloud on a software GPU so that the gallery keeps going when
the wall is off. At 05:00 the wall first tries to fetch the cloud piece from the gallery
(`display/daily.py: fetch`) and only composes its own after 10:00 if the cloud has not delivered. With no
internet it composes an offline piece.

## What visitors see

The site is generated by `tools/build_gallery.py` from `gallery/` plus `site/`:

- `art/` the feed, newest first, under a calendar of the year in colour;
- `e/<date>/` one page per edition with sliders to play the piece by hand and save a postcard;
- `window/` any screen as a small wall (full screen, LED dots);
- `feed.xml` RSS and `editions.json`;
- `index.html` is the wall's control app (see [remote-access.md](remote-access.md)).

Preview locally:

```bash
python3 tools/build_gallery.py --from assets/daily --out /tmp/site
python3 -m http.server -d /tmp/site 8000
```

## Running it for your own fork

By default the code points at the author's repository (`fionnf/magic-mirror`). There are five
things to change. All of them are listed with file paths in the README's "Make it yours".

1. **Fork the repo** and, in the fork, Settings, Pages, set the source to **GitHub Actions**.
2. **Repository secrets** (Settings, Secrets and variables, Actions): `OPENAI_API_KEY` (the default
   provider, see `config.AI_PROVIDER`) and/or `ANTHROPIC_API_KEY`. If only the Anthropic key is
   present, `ai_client.provider()` switches to Claude by itself. Optional repository *variable*:
   `WALL_MOODBOARD` (`user/board` of a public Pinterest board).
3. **Time zone.** `daily.yml` sets `TZ: Europe/Zurich` and its two cron lines are in UTC for Zürich.
   Change both for your location. (The wall's own schedule follows the Pi's time zone.)
4. **Site address.** `gallery.yml` runs `python3 tools/build_gallery.py` without `GALLERY_URL`, so the
   RSS feed and absolute links use `https://fionnf.github.io/magic-mirror/`. Add
   `env: GALLERY_URL: https://<you>.github.io/<repo>/` to that step (or edit `SITE_URL` in
   `tools/build_gallery.py`). Also change `TITLE`, `CREDIT` and `TAGLINE` there.
5. **Where the wall reads and writes.** In the wall's `.env`:

   ```
   GALLERY_REPO=<you>/magic-mirror
   GALLERY_RAW=https://raw.githubusercontent.com/<you>/magic-mirror/master/gallery/
   GALLERY_TOKEN=<fine-grained token, Contents: read and write, on that one repo>
   ```

   Instead of a token the wall can push with an SSH deploy key stored at `~/.ssh/fortuna_deploy`
   (a write-enabled deploy key on the repo; `GALLERY_DEPLOY_KEY` changes the path). On a laptop with
   the GitHub CLI logged in, `gh auth token` is used when `GALLERY_TOKEN` is empty. Without any of
   these the wall simply does not publish.

If you do not change `GALLERY_RAW`, your wall will fetch the **author's** daily pieces from his
public gallery, because that is the default. That is a convenient way to get a daily piece with no
keys at all, but it depends on his pipeline running.

Run the cloud artist by hand from the Actions tab ("Run workflow", optionally with a date), or
locally (needs an API key in `.env` and a GPU or `xvfb-run` with Mesa):

```bash
xvfb-run -a python3 tools/make_today.py            # today
xvfb-run -a python3 tools/make_today.py 2026-10-12 # one date
python3 -m display.publish 2026-10-09              # publish one edition by hand
```

Note that `gallery/` already contains the author's editions from October 2026; a fork inherits them.
